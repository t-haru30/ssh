# 日帰り旅程の操作

## 選んだルートを編集する

「見つける」や保存済みプランの詳細から「このルートで旅を計画する」を押すと、施設・順序・出発駅・座標・滞在時間を計画画面へ引き継ぐ。別の旅程がある場合は置き換え前に確認する。

出発駅・帰着駅、使える時間、予算、複数の好みを指定できる。金額が不明な項目は未確認として表示する。予定の固定、滞在時間の変更、施設の追加・削除・入れ替えは変更案を確認して反映する。

## 訪問済みの予定

タイムラインの「訪問済みにする」で表示中の開始・終了時刻を確認して記録する。記録した場所・時刻・滞在時間は、残りの予定を調整しても保持する。

訪問済みがある間は出発地・日付・出発時刻を変更できない。修正する場合は最後の訪問から順に解除する。通常のUndoでは訪問記録を取り消さない。実際の訪問時刻の自動計測は行わない。

## JSONで保存・復元する

「JSONを書き出す」で日帰り旅程の条件・施設・座標・固定・費用見積もり・訪問記録を保存する。

「JSONを読み込む」で内容を確認してから現在の旅程を置き換える。キャンセルや不正ファイルの場合は現在の旅程を保持する。上限は200KB・8施設。読み込んだ交通情報は未確認として扱い、必要に応じて交通経路を再検索する。AI要約やAPIキーは含めない。

## 駅名で検索する

「駅名で探す」から駅名を入力し、「駅を検索」を押す。同名駅は都道府県を見て選び分ける。「出発駅に戻る」を外すと帰着駅を別に指定できる。検索はサーバーに設定した駅すぱあとAPIを使用し、最大5候補を表示する。入力だけでは通信しない。

## 保存と制約

下書きはブラウザ内に保存し、端末間では自動同期しない。移動時間・施設料金には概算や未確認の項目を含む。当日の営業・休業日・実ダイヤを考慮した訪問可否は保証しない。

## 境界データを使った検証

47都道府県の境界検証では [geoBoundaries JPN ADM1](https://github.com/wmgeolab/geoBoundaries/raw/9469f09/releaseData/gbOpen/JPN/ADM1/geoBoundaries-JPN-ADM1.geojson)（ODbL 1.0、2017年の境界）を `backend/data/boundaries/jpn-adm1.geojson` に配置する。境界ファイルはGit管理外で、未配置の場合は対応するテストをskipする。


## 出発前の営業・移動チェック

編集画面の「営業・移動を確認して修正案を見る」から実行します。Google Placesの施設名と300m以内の座標を照合して営業状態と訪問日固有の営業時間を確認し、公式ページの対象日付き休業告知がある場合は優先します。公共交通は駅すぱあとで出発地点から帰着地点まで順に検索し、実到着時刻から待ち時間を含めて計算します。

不成立なら固定した施設・開始時刻と滞在時間を守り、開館待ちや訪問数の削減を一度試して全区間を再検索します。未確認や矛盾が残る案は採用できません。採用するまで元の旅程は変わらず、採用後も「ひとつ前に戻す」で戻せます。条件変更時は古い確認結果を破棄します。

対象は出発前の日帰り旅程、最大8施設です。訪問日固有の営業時間は原則、本日から7日間の取得範囲に限られ、それより先は未確認です。一時休業の登録は訪問日の再開を保証しません。最終入場や急な変更は施設での確認が必要です。訪問済み記録のある旅程には適用しません。現在の修正は開館待ち・訪問数の調整で、別施設への自動入れ替えは対象外です。

1回100秒、Google検索最大8件、経路は元と修正案の最大18区間、1プロセス同時1件・同一送信元毎分2件までです。営業時間検索はText Search Enterprise相当で、写真検索とは課金区分が異なります。GOOGLE_PLACES_API_KEYとEKISPERT_API_KEYを使用します。GoogleデータはDBや保存プランに格納せずレスポンスはno-storeです。既存の検索回数カウンターを共有しますが、Cloud Run全体の費用上限ではありません。
# 旅選びの表示（ローカル改善）

- 施設DB・ID・保存する旅程の基盤にはOSMを残します。Google Placesの紹介文・分類・評価・通常営業時間は表示時に施設名と300m以内の座標を照合して取得し、Google Mapsの出典と区別して表示します。Googleの情報はDB・保存プラン・AI選定キャッシュに混ぜません。カードは表示中の1枚だけ、1回最大8施設・同時2施設、写真と共通の月間検索上限内で取得します。口コミ本文や生成サマリーは取得しません。通常営業時間は訪問日の営業を保証するものではありません。
- Placesを中心に見せる旅程詳細・編集の地図はGoogle Mapsを使います。表示用にはPlaces用とは別の `GOOGLE_MAPS_BROWSER_API_KEY` が必要です。同じ値が設定されている場合はブラウザーへ返しません。Maps JavaScript APIとRoutes APIを有効にしてHTTPリファラーとAPIの制限を設定してください。運用時はGoogle Cloudで作成した地図IDへの置き換えも可能です。現在の地図IDはGoogleの `DEMO_MAP_ID` です。
- 地図は「つながり（直線）」「電車・バス」「徒歩経路」を切り替えます。初期表示は直線です。「電車・バス」は周辺のGoogle路線図と、施設名による区間別のGoogle Maps乗換リンクを表示します。旅程の路線・時刻・運賃は駅すぱあとで確認します。Google Routes APIは日本の公共交通に非対応のため、このモードではGoogle Routesを呼びません。路線図を選択した旅程の実経路とは表示しません（[Google公式FAQ](https://developers.google.com/maps/faq#transit_directions_countries)）。
- 「徒歩経路」を押した時だけGoogle Routesで施設間の道路経路を取得し、緑で表示します。対象は直線距離3km以内の施設間で、実際の歩行距離が3km以内であることは保証しません。徒歩の参考表示であり、公共交通の旅程や所要時間を変更しません。長距離区間は徒歩に置き換えません。「観光エリア」と「全体」で範囲を切り替えられます。
- Google Routesの徒歩検索は1回最大9区間・同時2区間、待機40秒、同じ画面内の取得結果を再利用します。アプリ側では写真・施設紹介と共通の `GOOGLE_PLACES_MONTHLY_LIMIT` 内で呼び出し数を予約します。Googleへのブラウザーからの直接通信のため、この予約は課金上限を保証しません。本番の上限はGoogle CloudのAPI割り当ても設定してください。Googleの経路・紹介文は画面内だけで扱い、施設DBや保存旅程には記録しません。
- `GOOGLE_MAPS_ROUTE_PROVIDER=ekispert` を明示した場合は「電車・バス」で駅すぱあとシェイプAPIを使います。15分有効のトークンで直前の検索結果を参照し、鉄道は線路、バスは停留所間、徒歩は接続地点間の目安を表示します。現在のキーでは403となるため、この機能の利用には駅すぱあと側の契約範囲の確認が必要です。失敗した区間を推測の実経路で埋めません。
- 候補は施設集合で重複を除き、同じ起点でも別施設を含む旅程は残します。AIの候補が少ない時は、同じ条件を満たす登録施設の別の組み合わせで補完します。候補数を増やすために食事・時間・地域の条件を緩めません。
- 「この旅の楽しみ」は全施設と朝昼夜の食事を含む一日の流れを紹介し、全文では施設ごとの特徴・選定理由と出典を表示します。Placesの紹介文がある場合はその情報を優先し、料理・人気・雰囲気などの未確認事項を創作しません。
- mainの `9bd67f4`（説明文の整理）を取り込み、ローカルの食事・経路確認などの機能は維持しています。
- AIの提案タグは「地元の名物を味わう」「庭園を散歩する」など、楽しみ方が伝わる具体的な表現で生成します。
- 施設の実写真を優先し、未取得時は施設名・カテゴリ・料理種別に対応したジャンル画像を表示します。和食・天ぷら・寿司・ラーメン・そば・焼肉・カフェ・和菓子・博物館・美術館・寺院・神社・庭園・自然・城・街歩きの16種類を追加し、料理種別が不明な飲食店は汎用画像を使います。AI生成の表示とジャンル名は画像の右上に置きます。生成指示と配置は `frontend/public/images/category-detail-atlas-v1.json` に記録しています。
- 点検の経過・出典・概算の算出方法は閉じた補足にまとめ、カードでは見どころを優先します。確認が必要な条件や変更案は補足を開いて確認できます。
- 好きな過ごし方は複数選択できます。「おまかせ」は他のテーマと排他的です。候補の検索範囲は選択テーマの和集合で、未充足のテーマを優先して組み合わせます。
- 地図と旅程は常に同時に表示します。スマホでは地図を上部に残し、旅程をスクロールできます。表示切り替えのタブはありません。
- 右スワイプは緑、左スワイプはオレンジに変化します。ラベルとボタンも併用します。
- 「どれくらい楽しむ？」の回答後に朝・昼・夜ごはんを複数選択できます。食事なしも選べます。半日に収まらない時間の組み合わせは案内を表示します。
- 食事の未回答と「食事なし」は区別します。グルメの好みで未回答・おまかせの場合、半日／長さ未指定は昼食、1日は昼食・夕食を組み込みます。明示的な食事なしでは飲食店を追加しません。
- 近場に候補が多くても、選択した食事に必要な飲食店数と好みが揃わない場合は検索範囲を縮めません。指定した最大半径・県境条件は維持します。オンライン候補が空でも、同じ条件を満たす未閲覧のローカル候補がある場合は補完します。
- 選んだ食事のみ任意の時刻欄を表示します。未指定は朝8:30・昼12:00・夜18:00を目安にし、指定時刻を守れる候補を探します。施設が足りない場合や時間に収まらない場合に食事を捏造・黙って削除しません。
- 食事までの余白は自由時間として計算します。カード・詳細・編集へ食事時刻と観光開始の目安を引き継ぎます。営業時間や朝食メニューの提供を確認済みとするものではありません。往路を含めた実際の移動は編集で再確認できます。
