# 入力と旅程編集の改善

PR #50の公開後に8011へ追加した変更。公開版への追加反映は別のリリースで行う。

- 「誰と出かけますか？」は4つの選択肢を2列で表示し、最後の「指定しない」は2列を使う。
- 「次へ」を無効にする理由を、未回答・食事時刻の矛盾・現在地の取得中に分けて、ボタンの近くと支援技術へ伝える。前の食事条件は属性画面の進行を妨げない。
- 「AIで行き先を提案」を削除。出発地点 → 都道府県 → 観光の起点の順に選ぶ。
- 起点候補は県境内・12km以内のOSMの駅を取得し、Places Nearby Searchの照合結果を優先。Placesで見つかった未登録の駅は最大2件を駅すぱあとでも独立検索し、同じ名前・近接位置・県境を確認して追加する。Google由来の施設名・座標・本文は保存しない。検索中や失敗時も既存の駅と駅名検索を使える。
- 自由入力は`priority_text`として一般タグと分け、AI・サーバーの代替生成・ブラウザー内の代替生成のすべてで優先する。施設名・ジャンル・公開された説明に一致する希望を使い、県境・距離・時間・食事条件は維持する。
- 編集を開くと区間単位で公共交通の経路を自動検索。全体一括検索が先に失敗して区間検索を妨げる処理を除去。取得済み区間を保持し、移動・滞在を含む総時間を表示。条件変更時に古い応答を破棄し、失敗時は再検索できる。
- 翌日帰着または14時間超の旅程で宿泊を提案。交通未確認の500km超の旅行は宿泊の検討を案内。観光の起点から5km・県境内のOSM宿泊施設をPlacesと照合して最大3件提示する。元の旅程は変更せず、空室・宿泊料金は未確認と明示する。

Places呼び出しは駅候補・宿泊候補それぞれ最大1回。既存の月間利用上限を共有し、上限の変更・追加キーは不要。OSMのみ6時間・64件のメモリーキャッシュを使う。Placesの応答は照合に使うリクエスト内に限定する。

公開Overpassが混雑した際の補完として、2026-10-14にOSM公式APIの小さい地図範囲から独立取得した119件（駅11件・宿泊108件、京都・盛岡・金沢・岐阜の駅周辺）を同梱する。ノード・ウェイのOSM情報だけを保持し、投稿者情報・Google情報は含まない。返す際は同じ県境・距離制約で絞り、Googleの営業状況は毎回の検索結果を使う。

参照：[Nearby Search](https://developers.google.com/maps/documentation/places/web-service/nearby-search)、[Placesの保存と表示のポリシー](https://developers.google.com/maps/documentation/places/web-service/policies)。

駅すぱあと駅検索のHTTP接続も、経路検索と同じOS標準の信頼済み証明書を使う。証明書検証を有効にしたまま、ローカルで駅検索だけが失敗していた差異を解消した。
