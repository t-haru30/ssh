# 口コミ・公開情報のAI要約

旅程の各施設と「見つける」のルート詳細から「口コミ・公開情報を調べる」を押すと、Gemini APIのGoogle検索連携で情報を取得する。画面表示だけでは検索しない。

## サーバー設定

AI要約は既定で無効。次の環境変数を設定すると有効になる。

| 環境変数 | 用途 |
| --- | --- |
| `VENUE_EVIDENCE_ENABLED` | `1`で有効化する。 |
| `RECOMMENDATION_GEMINI_API_KEY` | AI要約専用のAPIキー。Secret Manager等で管理し、ソースコードやブラウザへ渡さない。 |
| `RECOMMENDATION_GEMINI_MODEL` | Google検索対応モデル。既定値は `gemini-3.8-flash`。 |

通常の `GEMINI_API_KEY` とは別の設定で、専用キーがない場合に代用しない。`GET /api/recommendations/status` は設定の有無を返し、キーの値は返さない。

## 取得と表示

- 検索対象は施設名・住所・座標。旅程全体、旅行日、好み、利用者の現在地は送らない。
- 口コミ・公式情報・注意点を短く表示し、本文に対応する参照リンク、取得日、Googleの検索候補を表示する。取得日は資料の公開日や更新日とは異なる。
- 施設名・住所・位置と検索の根拠を照合する。施設の特定や説明の根拠を確認できない応答は要約として表示しない。星評価や口コミ件数を生成しない。
- 結果は表示中のコンポーネントのメモリだけに保持し、DB・ログ・下書き・保存済みルート・JSONへ保存しない。
- 営業時間・最新料金・当日の営業は保証しない。料金を予算へ自動加算せず、旅程の選択・固定・滞在時間を変更しない。

## 利用量の制限

1回のボタン操作につき生成リクエストは1回で、自動再試行は行わない。1プロセス20回、同時1件、同一接続元は毎分6回まで。失敗も20回の上限へ数え、再起動でリセットされる。

この制限は複数インスタンス全体の費用上限ではない。1回の生成で複数の検索が行われる場合もあるため、提供元の利用量・課金設定を別途管理する。
