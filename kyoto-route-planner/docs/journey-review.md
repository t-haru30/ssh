# 出発前の施設情報確認

日帰り旅程の「出発前の情報をまとめて調べる」から、現在の行き先の公式情報を確認できます。`POST /api/journey/review` は `places` と `departure_date` を受け取り、確認結果・出典・実行した手順・未確認項目を返します。

## 確認手順

1. 訪問順に先頭3施設を選び、公式ページの営業時間・休館日・料金を調べます。
2. 項目がそろっている施設は追加検索を省略します。
3. 不足する施設だけ、既存のGoogle Search groundingによる出典付き検索を最大2回実行します。取得できた公式URLは次の検索へ引き継ぎ、その案内を優先して調べます。施設の一致と事実の出典は改めて検証します。AI検索は `VENUE_EVIDENCE_ENABLED=1` と共有のGeminiキーがある場合だけ動きます。
4. 取得失敗や時間上限があっても、得られた公式案内と未確認の項目を返します。

AI要約は公式ページから直接確認できた項目と分けて表示します。出発日は訪問予定の表示に使い、指定日の営業や入場可否の自動判定は行いません。臨時休館・最終入館・予約条件は、表示した公式リンクで確認できます。

## 実行と保存の制御

- 全体45秒。公式情報の取得は1施設13秒（内部の取得上限12秒と返却の余裕）、AI検索は1回12秒まで。
- 1プロセスで同時1件。待ち時間も全体の制限時間に含めます。
- エンドポイントはIP単位で2回/分。既存の外部API共有制限も適用します。
- 手動操作で開始し、ブラウザ側は50秒で待機を終了できます。旅程や日付の変更時は古いリクエストを中止し、遅れて届いた結果を表示しません。
- 検索で得たAI本文と出典は表示中のメモリにだけ保持し、旅程の下書き・お気に入り・JSON・DBへ保存しません。

別の施設の結果を混ぜないこと、回数と時間の上限、根拠の保持、途中結果の返却、旅程変更時の破棄をテストしています。

公式URLの探索とページの抽出については[公式案内の取得](official-visitor-info.md)を参照してください。
