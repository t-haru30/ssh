# ConcierGO：変更の引き継ぎとCloud Runへの反映

更新日：2026年10月12日。対象：`feature/my-task` → `main` のレビュー用PR。最新mainを統合して検証済み。**mainへのマージ・Cloud Runへの反映は行っていない。** この文書はレビューと、承認後の反映準備のための引き継ぎ資料。

## チームに送る文面

次の短い文面にPRのリンクを添えて伝えられる。

詳しく伝える場合：

> ConcierGOの日帰り旅程編集とUIを改善しました。選んだスポットの引き継ぎ、初回提案への時間・予算の反映、独立した帰着地、複数の好み、固定・部分編集、訪問済み予定の保護、JSON保存・復元、駅名検索を追加しています。地図をカラーに戻し、口コミ等のAI要約は短く整理しました。
>
> 最新mainのPR #36まで統合し、ローカルのテスト360件とビルドが成功しています。路線名・区間の発着時刻、昼食候補と理由、現在地からの出発に対応した詳細表示も保持しています。共有サーバーは未変更です。レビュー承認後にCloud Runへ反映する手順を資料にまとめました。
>
> UIと旅程の引き継ぎ・復元を中心にレビューをお願いします。AI要約は任意機能です。共有環境で有効にする場合は、チーム用キーと利用量の管理を決める必要があります。変更点・設定・確認手順・戻し方は `docs/team-handoff.md` にまとめました。

## 変更した動作

| 項目 | 変更後の動作 |
| --- | --- |
| 選んだ行き先 | 「見つける」から選んだ施設・座標を旅程に引き継ぐ。別の旅程を開く際はアプリ内で置き換えを確認する。 |
| 初回提案 | 使える時間・予算・飲食等の見積もりを入力し、初回の旅程に反映する。金額が未確認の項目は明示し、予算内と断定しない。 |
| 帰着地と好み | 出発地と異なる帰着地を指定できる。好みを複数選び、登録カテゴリや名称に基づく推薦理由を表示する。 |
| 固定と部分編集 | 行き先・滞在時間を固定し、任意で開始時刻を指定する。入れ替え・追加・削除や時間・予算の調整は、変更案を確認してから反映する。 |
| 訪問済み | 訪問順に表示中の時刻を記録し、場所・時刻・滞在時間を保護する。残りの予定だけ調整できる。最後の訪問から確認付きで解除でき、通常のUndoで記録は消えない。 |
| JSON | 日帰りの条件・施設・座標・固定・訪問記録を保存・復元する。上限200KB・8施設。読み込み前に内容を確認し、不正ファイルやキャンセル時は現在の旅程を保持する。 |
| 駅名検索 | 出発駅と帰着駅を自由入力で検索できる。同名駅は都道府県を見て選び、実際の座標を引き継ぐ。最大5候補。入力だけでは通信しない。 |
| 地図とUI | カラー地図、旅行イラスト、カード・タイムライン・確認画面を整備。スマートフォン幅でも横にはみ出さないことを確認した。 |
| AI要約 | 押した施設だけGoogle検索連携で情報を取得する。口コミ・公式情報・注意点を短く表示し、施設の照合情報と参考ページ一覧は折りたたむ。「出典付き」の強調は外し、参照リンクは保持する。 |
| 保存 | 日帰りの下書き、検索条件、表示タブをブラウザに保存する。AI要約は画面のメモリだけに保持する。 |

主な実装は `frontend/src/DayTripEditor.tsx`、`dayTrip.ts`、`initialTrip.ts`、`journeyDraft.ts`、`journeyFile.ts`、`JourneyFileControls.tsx`、`StationSearch.tsx`、`searchState.ts`、`VenueEvidence.tsx` と `backend/app/main.py`、`models.py`、`station_search.py`、`venue_evidence.py`。画面スタイル、地図、画像、各機能のテストも含む。

## 最新mainとの関係

- 機能実装はローカルコミット `0a8bac6`（`feat: add editable day trips and venue summaries`）に保存した。
- `origin/main` の `612d9f2` を統合した。保存機能（PR #32）、海をまたぐ候補の除外（PR #33）、都道府県ごとの出発駅・区間時間等（PR #34）、交通情報の補正（PR #35）、昼食計画とConcierGOへの名称変更（PR #36）を含む。
- 詳細画面・保存済みルート・計画画面への引き継ぎに、最新データの出発駅と座標・滞在時間を反映した。詳細には区間ごとの移動手段・時刻・昼食・帰着時刻を表示し、時間の絞り込みは実際の所要時間に基づく `course` を使う。
- PR #34の生成データから `theme` が抜けており、好みによる絞り込みや保存を妨げるため修正した。生成スクリプトで分類を出力し、既存235ルートは生成済みタイトルに記録された分類を復元。検証スクリプトと回帰テストを追加した。新しい出発駅・区間データは保持している。
- ブラウザ保存のテストも、現在の編集画面と日帰り下書きへの移行に合わせて統合した。
- PR #35・#36の詳細プレビューは、表示時に交通APIで路線名・発着時刻を補正し、取得できないときは生成データの見積もりを残す。施設ごとの滞在時間と最大8施設に対応し、独立した帰着地も区間検索の終点に渡す。現在地からの計画にも選んだ出発座標を引き継ぐ。
- 新しい昼食候補・推薦理由・時間帯の注意表示を保持した。計画画面のスワイプ開始ボタンはmainの変更に合わせて表示しない。

レビュー時はPRの差分、または `git log --oneline origin/main..feature/my-task` と `git diff origin/main...feature/my-task -- kyoto-route-planner` で変更を確認できる（Gitルートから実行）。

| `RECOMMENDATION_GEMINI_MODEL` | AI要約の任意設定。現在の既定値は `gemini-3.8-flash`。利用可能な検索対応モデルを確認する。 |
| `GEMINI_API_KEY` | 既存のタイトル・ストーリー生成用。AI要約用キーとは別。 |

この変更によるDBスキーマ変更はない。旅程の下書き・固定・訪問記録・JSON入出力はブラウザ内で処理する。サーバー起動時の既存DB初期化は従来どおり動くため、既存のDBパスやマウント設定は維持する。

ローカルの `.local/personal-api.env`、`.local/dev.sqlite3`、通信ガード、テスト用ログは共有しない。ローカル専用ランチャーの通信遮断はCloud Runでは動かない。共有サービスの認証・ネットワーク・秘密情報の設定はCloud Run側の管理を引き継ぐ。

ソースアップロード用 `.gcloudignore` とDockerビルド用 `.dockerignore` を追加した。プロジェクトの `.gitignore` に従い、個人用設定・DB・仮想環境・キャッシュ等を除外する。ビルド・アップロードの起点は `kyoto-route-planner/`。

## 残る制約

- 表示中の時刻を訪問記録にする。実際の訪問時刻の自動測定は行わない。
- 移動は概算を含む。施設ごとの営業時間・休業日・当日の実ダイヤを考慮した訪問可否の保証はない。
- 候補の詳細は生成データの区間別見積もりを起点とし、交通APIが利用できる場合は路線名・発着時刻を補正する。編集画面は交通経路を検索するまで座標から概算するため、詳細の所要時間と一致しないことがある。
- JSONは現在の日帰り旅程向け。AIの説明文・提供元の交通応答は含めず、交通情報は未確認として再計算する。
- 端末間・ユーザー間で旅程は自動同期しない。ローカルから共有URLへ持ち出す場合はJSONを使う。
- AI要約は1プロセス20回・同時1件・IPごと毎分6回まで。20回制限は再起動で戻り、Cloud Runの複数インスタンス全体の費用上限にはならない。課金と利用量の管理は別途必要。
