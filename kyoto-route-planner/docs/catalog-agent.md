# 施設情報の自動更新エージェント

提出版の構成。公開反映と実測の記録は [cloud-production-check.md](cloud-production-check.md)、導入手順は [cloud-beginner-handoff.md](cloud-beginner-handoff.md) を参照。

## 実行と判断

Cloud Schedulerが10分ごとにCloud Run Jobを起動する。Jobは期限を迎えた施設を最大3件確認して終了する。Cloud RunのWebサービスでは常駐更新ワーカーを開始しない。

公式情報の取得処理が対象施設との対応を確認してページを取得し、営業時間・休業日・料金を抽出する。Geminiは抽出結果と前回値を評価して、採用する項目・再取得・要確認を選ぶ。再取得は1施設につき追加1回までで、Gemini判断は最大2回。更新対象や次回期限はサーバーのルールで決める。

Geminiの出力は行動・対象項目・理由に限定する。値・URL・日時は生成させず、出典のある取得値だけを保存候補にする。サーバーがすべての取得項目を比較したうえで、保存可否を検証する。

- 根拠のある項目を採用できた場合：保存し、次回期限を30日後にする。
- 前回値との差分や休業告知：前回値を保持し、差分と理由を記録する。
- 根拠不足・取得失敗・モデル失敗：前回値と確認日時を保持する。再試行間隔は1時間から最大7日まで延ばす。
- 今回取得できなかった項目：消去せず、その項目の前回の確認日時を保持する。
- 不正なモデル応答：保存しない。ルールのみの成功へ切り替えない。

履歴にはモデル名、判断した行動・理由・採用候補、判断に渡した取得結果を残す。旧来のルールだけによる確認履歴はGemini判断として扱わない。

## 永続化と実行上限

クラウドではFirestoreに対象キュー、採用情報、全試行の履歴、次回期限、日次予約数を保存する。元の施設マスターJSONは変更しない。管理画面は元データと採用値を結合したAPIを読む。

1日100件の処理予約を上限とし、失敗や途中停止も件数を消費する。Firestoreのトランザクションで15分の処理権を確保し、保存時にもその権利を検証する。これは処理量の制限であり、金額や更新成功件数の保証ではない。採用後30日は次回期限であり、全施設を30日以内に更新する保証ではない。

## 管理画面と確認範囲

管理用Cloud RunサービスはIAM認証必須。公開Webでは管理画面・管理APIを拒否する。クラウドでは管理画面からのHTTP手動更新も拒否し、認証されたJob実行だけで更新する。

- GET `/api/catalog-agent`：状態、直近50件の履歴、根拠、差分、次回期限。
- GET `/api/catalog-agent/catalog`：施設一覧に公式確認結果を結合。
- `/facility-catalog.html`：認証された運営者向けの確認画面。

確認済みの営業時間・休業日・料金は、旅程生成時に施設IDで結合し、旅程カードの画像から開く施設詳細にも反映する。保存済みの古い旅程でも、詳細を開くと現在のDB情報を取得する。開いている詳細は60秒ごとと画面へ戻ったときに再取得し、出典と項目別の確認日を表示する。サーバーの読み取りキャッシュは30秒のため、更新の表示まで最大約90秒かかる場合がある。

公開画面はPOST `/api/places/current-information` に施設IDを最大60件渡し、確認済みの項目だけを読み取る。管理用API・判断履歴は公開しない。要確認や取得失敗の場合は前回の採用値を保持し、一時的なDB接続失敗でも表示済みの値を消さない。自動再取得ではGoogle Maps・Geminiを呼ばない。要確認を承認・編集する画面は含まない。公式ページの記載を確認できても、当日の営業を保証するものではない。

## ローカル開発

SQLiteはローカル確認用。`CATALOG_ADMIN_ENABLED=1` を指定し、ループバックからアクセスする。実験側は8000、公開側のローカル確認は8011を使い分ける。`CATALOG_AGENT_ENABLED=1`、SQLite、Cloud Run外という条件を満たすと、起動時とバッチ終了から5分ごとにローカルワーカーが動く。

`CATALOG_AGENT_DB` でSQLiteの保存先を指定できる。POST `/api/catalog-agent/run` はローカル・同一Originからのみ実行できる。ローカル常駐ワーカーの設定と、クラウドのScheduler停止・再開は別の操作である。

URL取得には既存の公開IP固定・リダイレクト検査・応答サイズ制限・時間制限を使う。外部ページ内の指示は命令として扱わず、取得内容は実行せずテキストとして表示する。
