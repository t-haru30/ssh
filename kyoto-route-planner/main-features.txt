京都よりみちルート
mainブランチ搭載機能まとめ

確認対象
---------
mainブランチ（確認時点: 2026-10-06）

概要
----
京都駅周辺の観光スポットをテーマ別に選び、駅すぱあとAPIで公共交通ルートを検索して、
1日の寄り道ルートを提案するアプリです。

フロントエンドはReact、TypeScript、Vite、MapLibre GL JSで構成されています。
バックエンドはFastAPIで、OpenStreetMap/Overpass APIからスポット候補を取得し、
駅すぱあとAPIで交通経路を検索します。

画面から利用できる機能
----------------------

1. 条件を指定したルート提案

以下の条件を指定してルートを検索できます。

- 出発駅
  - 現状は実質的に京都駅のみ
- 出発日
- 出発時刻
- 立ち寄り件数（1〜3か所）
- 旅行テーマ
  - おまかせ
  - 歴史・文化
  - 神社・寺院
  - 自然・景色
  - 食・商店街

検索すると、テーマや地点間の近接性をもとに候補スポットを選び、
出発駅からスポットを経由して出発駅へ戻る公共交通ルートを検索します。

2. 複数ルート候補の表示

- 最大3パターンのルート候補を表示
- 電車・バス・徒歩などの経路区間を表示
- 推定所要時間を表示
- 出発時刻・到着時刻を表示
- ルートごとの移動区間を表示
- 経路が見つからない候補を除外
- 検索全体に45秒のタイムアウト予算を設定

3. 地図表示

MapLibre GL JSとOpenFreeMapを使って、京都の地図を表示します。

- 出発駅を「出」マーカーで表示
- 立ち寄り先を番号付きマーカーで表示
- マーカー選択時に地点名を表示
- 複数地点が収まるように自動ズーム
- 地点が1つの場合はその地点へ移動
- OpenStreetMap/OpenFreeMapの帰属表示を掲載

地図は地点の位置確認用であり、交通経路の線は描画しません。

4. 状態・エラー表示

- 候補地の読み込み中表示
- ルート検索中表示
- APIタイムアウト表示
- 候補地が取得できない場合のエラー表示
- 条件に合う経路がない場合のエラー表示
- Overpass APIの利用制限・一時停止表示
- 不正なAPIレスポンスの検出

リクエストのキャンセル、タイムアウト、レスポンス形式の検証も実装されています。

スポットデータ取得
------------------

1. Overpass APIによるスポット取得

APIキー不要のOverpass APIからOpenStreetMapのスポット情報を取得します。

対象カテゴリの例:

- 観光地
- 歴史的地点
- 自然・公園・庭園
- 神社・寺などの宗教施設
- レストラン・カフェ・飲食店
- 商店・市場など

対象範囲は京都駅を中心とした半径2km圏内です。

取得結果はローカルSQLiteに24時間キャッシュされます。

- HTTP 429の場合はRetry-Afterを考慮
- Overpass障害時は利用可能ならキャッシュを使用
- 一時的な障害はエラーとして表示
- 無限リトライは行わない

2. テーマによる候補地選定

スポットのカテゴリ、名称、OpenStreetMapタグなどを使って、
指定テーマに合う候補地を選びます。

候補の訪問順は主に地点間の近接性を考慮します。
観光上の最適順、営業時間、混雑状況、最新の営業状態は保証されません。

自然文スポット検索API
----------------------

画面の通常ルート検索とは別に、自然文でスポットを検索するAPIがあります。

エンドポイント:

POST /api/search/places

入力例:

{"query":"京都駅周辺で自然を感じられる場所"}

ルールベースで以下の条件を抽出します。

- 地域
- 登録済み出発駅
- カテゴリ
- 雰囲気（自然、歴史、都会など）
- 対象者（子連れ、カップル、シニアなど）
- 活動タイプ（食べ歩き、鑑賞、リラックスなど）
- 半径指定
- 徒歩時間指定

検索対象はOverpass APIから取得したキャッシュ済みの
OpenStreetMapスポットです。

未導入の機能:

- LLMによる意味理解
- ベクトル検索
- 高度な自然言語解析
- 未登録駅・地点への柔軟な位置解決

自然文からの周遊ルートAPI
--------------------------

自然文検索結果から、より詳細な周遊ルートを作成するAPIがあります。

エンドポイント:

POST /api/itineraries

主な処理:

1. 自然文から候補スポットを検索
2. 最大3か所を選択
3. 立ち寄り順の全順列を比較（最大6通り）
4. 各順番について駅すぱあとAPIで公共交通経路を検索
5. 公共交通の所要時間が最短の順番を採用
6. 各スポットの滞在時間を加算
7. 指定帰着時刻に間に合う見込みを判定

デフォルトでは、1か所あたりの滞在時間を90分として計算します。

レスポンスに含まれる情報:

- 採用されたスポット
- ルート区間
- 公共交通の所要時間
- 推定帰着時刻
- 帰着期限内かどうか
- 駅すぱあとAPIの呼び出し回数
- 計算上の注意事項

このAPIはバックエンドに実装されていますが、現状のフロント画面には
自然文入力や帰着時刻指定の専用UIはありません。

国土数値情報P12のローカル検索基盤
----------------------------------

将来的な検索基盤として、国土数値情報の観光資源データ（P12）を
SQLiteへ取り込む機能があります。

保持できる情報:

- データセット情報
- スポット名、住所、座標
- 原典レコードID
- 原典属性JSON
- 雰囲気・対象者・活動タイプのラベル
- FTS5による文字列検索
- R*Treeによる空間検索

P12データは再実行可能な取り込み処理と、
キーワードルールによるラベル付け処理に対応しています。

ただし、P12データの利用条件により、現状はローカル・非公開用途に限定されています。
現在の画面上のスポット候補は、P12ではなくOverpass/OpenStreetMap由来です。

API一覧
-------

GET  /api/health
     APIの稼働確認

GET  /api/places
     画面用のスポット候補一覧を取得

GET  /api/origins
     出発駅一覧を取得

GET  /api/places/status
     Overpassのキャッシュ・取得状態を取得

POST /api/search/places
     自然文でスポットを検索

POST /api/itineraries
     自然文条件から詳細な周遊ルートを作成

POST /api/routes
     テーマ、出発日時、立ち寄り件数からルートを提案

主な制約
--------

- 対象エリアは京都駅周辺2km
- 出発駅は現状、京都駅のみ
- 四条、三条、嵯峨嵐山周辺は対象外
- 駅すぱあとAPIキーが必要
- 駅すぱあとAPIキーはバックエンドだけで利用
- 営業時間、混雑、乗車遅延は考慮しない
- スポット滞在時間は基本的に一律90分という仮定
- 地点から駅までの徒歩経路は実測せず、座標から概算
- 地図上の交通経路線は未実装
- OverpassおよびOpenFreeMapの稼働保証はない
- 自然文検索はルールベースで、LLM・意味検索は未導入
- P12データは利用条件により公開・再配布できない可能性がある

まとめ
------

mainブランチの中心機能は、以下のとおりです。

京都駅周辺のOpenStreetMapスポットをテーマ別に選び、
駅すぱあとAPIで実際の公共交通ルートを検索し、
最大3つの候補を地図と一覧で提示するアプリです。

さらにバックエンドには、画面から直接利用していない基盤機能として、
以下も実装されています。

- 自然文によるスポット検索
- 最大3地点の順列比較による周遊ルート作成
- 帰着時刻内に収まるかの概算判定
- 国土数値情報P12のローカル取り込み・ラベル付け・検索基盤
